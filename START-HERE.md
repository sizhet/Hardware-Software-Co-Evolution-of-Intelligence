# 1. The Shortest Possible Introduction

This repository starts from one question:

> **Why should intelligence begin only after representation?**

Modern AI often assumes:

```text
World
  ↓
Sensing
  ↓
Representation
  ↓
AI Model
  ↓
Decision
```

HSCI explores a broader path:

```text
Physical Difference
        ↓
Selective Coupling
        ↓
Resonance / Amplification
        ↓
Salience
        ↓
Structural Consequence
        ↓
Trigger / Routing
        ↓
Selective Representation
        ↓
Higher Intelligence
```

The central proposition is:

> **Intelligence may begin before complete representation when a physical or sensory difference begins to alter what the system computes or does next.**

That idea is called:

# Intelligence Before Representation

# 2. The One Sentence to Remember

If you remember only one sentence from this repository, remember:

> **A system does not need to know what something is before it can know, structurally, that something matters.**

That distinction separates:

```text
Semantic Recognition
"What is it?"
```

from:

```text
Structural Recognition
"Does it matter?"
```

HSCI argues that the second can occur before the first.

# 4. HSCI Is Not “Hardware vs Software”

The title contains both hardware and software, but the framework is not a competition between them.

The deeper idea is:

# Hardware–Software Co-Evolution

```text
Hardware Bias
      ↓
Software Learning
      ↓
Repeated Structural Regularity
      ↓
Function Tunnel
      ↓
Validation
      ↓
Structural Consolidation
      ↓
New Hardware Bias
      ↺
```

Hardware can shape what is easy to perceive.

Software can discover useful regularities.

Repeatedly useful regularities may become candidates for cheaper structural realization.

The result is a co-evolutionary loop.

# 5. The Representation-First Assumption

A large fraction of modern AI can be summarized as:

```text
Represent First
     ↓
Compute Later
```

This is powerful.

HSCI does not reject it.

HSCI asks whether it should be universal.

For some functions, a better path may be:

```text
Select First
     ↓
Represent Only If Needed
```

This is especially important when:

```text
Energy is scarce
Latency is critical
Bandwidth is limited
Safety matters
The event is frequent
The distinction is structurally simple
```

# 6. Physical Difference Is Not Yet Intelligence

HSCI does **not** claim that all physics is intelligence.

For example:

```text
Photon
  ↓
Voltage
```

is not automatically intelligent.

The important transition occurs when a difference begins to alter downstream structure.

Examples:

```text
Increase Attention
Switch Route
Activate Controller
Trigger Emergency Mode
Write Memory
Call ANN Specialist
Change Action
```

That transition is central to HSCI.

# 7. Structural Consequence Boundary — SCB

HSCI introduces:

# Structural Consequence Boundary

The SCB is the transition where a physical or sensory difference begins to alter:

* routing,
* computational state,
* attention,
* control,
* memory,
* or action.

Conceptually:

```text
Physical Signal
      ↓
Transformation
      ↓
Selective Response
      ↓
Salience
      ↓
---------------------- SCB
      ↓
Structural Consequence
      ↓
Trigger / Routing
      ↓
Behavior
```

The SCB is not necessarily one exact physical point.

It may be a transition region.

The concept helps avoid two extremes:

```text
Only reasoning is intelligence
```

and:

```text
Every sensor response is intelligence
```

# 9. Resonance Is Important — But Use the Term Carefully

Resonance provides a useful model of selective response.

A system may respond much more strongly to one physical pattern than to others.

```text
Environmental Pattern
        ↓
Selective Coupling
        ↓
Strong Response
```

This can help produce salience.

But:

```text
Resonance ≠ Pleasure
```

A more careful chain is:

```text
Resonance
    ↓
Salience
    ↓
Possible Valence
```

HSCI does not claim that subjective pleasure can be reduced to resonance.

The narrower idea is that selective physical response can help establish important structural anchors.

# 10. Anchor, Trigger, Organizer

A salient event may perform three distinct functions.

## Anchor

> **THIS matters.**

The event becomes a local reference point.

## Trigger

> **ACTIVATE this path.**

The event changes what happens next.

## Structural Organizer

> **ORGANIZE surrounding information around this point.**

This is especially important because it may help build later representation.

# 19. The Smallest Sufficient Intelligence Principle

The core engineering rule is:

> **Put the smallest sufficient intelligence at the earliest effective layer.**

The key word is:

# Sufficient

A smaller mechanism is not useful if it is unsafe or unreliable.

The objective is not minimum computation at any cost.

The objective is:

```text
Minimum Necessary Complexity
        +
Required Reliability
        +
Required Safety
```

> **Capability hierarchy is not authority hierarchy.**

# 32. What to Look for When Reading

Do not read HSCI as a claim that hardware should replace software.

Instead, repeatedly ask four questions.

1. **Selection**
   What differences are being selected?

2. **Structural Consequence**
   Does that selection change routing, state, control, or action?

3. **Placement**
   At which substrate should the function live?

4. **Escalation**
   What happens when this substrate is not sufficient?

These four questions capture most of the framework.
