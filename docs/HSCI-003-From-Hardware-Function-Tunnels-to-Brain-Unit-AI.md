## Abstract

If intelligence can begin before general representation, then artificial intelligence architecture should not assume that every intelligent distinction must first be converted into a universal digital representation and processed by a general-purpose model.

HSCI-001 introduced **Hardware–Software Co-Evolution of Intelligence** as a multi-substrate framework.

HSCI-002 developed **Intelligence Before Representation**, in which physical selectivity, resonance, salience, triggering, and structural organization can produce intelligence-relevant consequences before complete semantic representation exists.

This paper asks the architectural question that follows:

> **Where should each intelligent function be physically and computationally realized?**

We introduce **Hardware Function Tunnels (HFTs)**: stable pathways in which physical or sensory selectivity maps recurring environmental differences into reliable downstream structural consequences.

The Function Tunnel concept is then generalized across multiple substrates:

```text id="q23kwo"
Physical FT
Sensor FT
Control FT
Boolean FT
CCC FT
ANN FT
World-Model FT
Cognitive FT
```

Together they form a **Multi-Substrate Function-Tunnel Network**.

This paper further develops **Per-Function Intelligence Placement**, in which intelligent functions are assigned to physical structures, sensors, analog circuits, Boolean logic, CCC triggering, ANN specialists, world models, LLMs, or human escalation according to energy, latency, computational cost, reliability, physical cost, and adaptability.

Two complementary runtime movements are proposed:

* **Selective Upward Escalation** — unresolved or uncertain distinctions move toward more flexible and computationally expensive intelligence;
* **Downward Structural Consolidation** — stable, frequently used, latency-sensitive distinctions become candidates for cheaper, faster, and more specialized implementation.

The resulting architecture supports **multi-substrate, multi-timescale, selectively routed intelligence**.

A future Brain-Unit AI is therefore not merely an LLM connected to tools.

It can be understood as a governed runtime coordinating physical intelligence, sensory intelligence, structural triggers, Function Tunnels, ANN specialists, world models, emergency pathways, LLM reasoning, and human participation.

The central engineering principle is:

> **Put the smallest sufficient intelligence at the earliest effective layer, and escalate only when necessary.**

# 3. Function Tunnel

A **Function Tunnel (FT)** is a structurally stable pathway through which a class of inputs or conditions repeatedly reaches a useful functional outcome without reconstructing the entire solution from scratch.

Conceptually:

```text id="5ujjui"
Condition Class
      ↓
Stable Structural Path
      ↓
Functional Outcome
```

The key properties are:

* repeated usability,
* structural stability,
* selective activation,
* reduced search,
* reduced recomputation,
* and predictable functional consequence.

A Function Tunnel does not necessarily require a literal fixed circuit.

It can exist as a stable structural pathway across multiple implementation forms.

# Hardware Function Tunnel — HFT

The important point is:

> **The physical structure has become part of the reusable intelligence path.**

# 5. Hardware Function Tunnel vs Hardware Accelerator

A Hardware Function Tunnel should not be confused with a conventional hardware accelerator.

An accelerator typically performs:

```text id="e5r0kr"
Known Computation
      ↓
Faster Hardware Execution
```

A Hardware Function Tunnel can begin earlier:

```text id="cklv45"
Physical Difference
      ↓
Selective Physical Response
      ↓
Structural Consequence
```

The hardware is not merely accelerating a computation already defined elsewhere.

It may participate in defining:

* what becomes visible,
* what becomes salient,
* what is ignored,
* what triggers computation,
* and which computational path becomes active.

Thus:

> **An accelerator makes computation cheaper.**

while:

> **A Hardware Function Tunnel may make some computation unnecessary.**

This distinction is fundamental.

# 7. Intelligence as a Network of Unequal Substrates

The substrates of intelligence are not equivalent.

Each has a different capability profile.

| Substrate          | Typical Strength                  | Typical Limitation         |
| ------------------ | --------------------------------- | -------------------------- |
| Physical structure | Extremely low compute and latency | Low flexibility            |
| Specialized sensor | Early selective discrimination    | Narrow domain              |
| Analog mechanism   | Fast continuous response          | Limited programmability    |
| Boolean logic      | Deterministic and auditable       | Low expressive flexibility |
| CCC                | Structural triggering and routing | Requires structural design |
| ANN                | Learned pattern discrimination    | Compute/data cost          |
| World model        | State and temporal modeling       | Representation cost        |
| LLM                | Open semantic reasoning           | High cost and latency      |
| Human              | Broad judgment and accountability | Slow and scarce            |

The architectural objective is therefore not:

```text id="c3fy24"

```

It is:

```text id="8j23un"
Find the best placement
for each intelligence function.
```

# 8. Per-Function Intelligence Placement

We define:

# Per-Function Intelligence Placement — PFIP

> **Per-Function Intelligence Placement assigns each intelligent function to the substrate or combination of substrates that provides sufficient capability under the relevant system constraints.**

For an intelligence function \(F\):

$$
P^*(F)
\coloneqq
\arg\min_{P \in \mathcal{P}}
J(F,P)
$$

where:

$$
\mathcal{P}
\coloneqq
\{
P_{\text{physical}},
P_{\text{sensor}},
P_{\text{analog}},
P_{\text{boolean}},
P_{\text{CCC}},
P_{\text{ANN}},
P_{\text{WM}},
P_{\text{LLM}},
P_{\text{human}}
\}
$$

A conceptual objective is:

$$
J(F,P)
\coloneqq
\alpha E
+
\beta L
+
\gamma C
+
\delta R
+
\epsilon W
+
\zeta A
+
\eta G
$$

where:

* \(E\) = energy cost,
* \(L\) = latency,
* \(C\) = computational cost,
* \(R\) = reliability / risk cost,
* \(W\) = weight or physical implementation cost,
* \(A\) = adaptation / flexibility cost,
* \(G\) = governance / verification cost.

The coefficients depend on the system.

There is no universally optimal substrate.

# 12. Why Selective Escalation Matters

Expensive intelligence is valuable precisely because it can solve difficult cases.

That does not mean it should solve every case.

Suppose:

```text id="kz9rpf"
95% routine
4% ambiguous
1% novel / dangerous
```

An architecture that sends 100% of cases to the most expensive substrate may waste substantial resources.

A selective architecture can use:

```text id="ubkqkx"

   ↓
Small FT

Ambiguous
   ↓
ANN / World Model

Novel
   ↓
LLM / Human
```

This allows powerful intelligence to concentrate on the cases where its flexibility has the highest marginal value.

# Downward Structural Consolidation — DSC

# 22. Why One Clock Is Inefficient

Consider a collision event.

A physical trigger may need to respond within milliseconds.

A world model may need tens or hundreds of milliseconds.

An LLM may operate at a much slower semantic timescale.

Forcing the entire intelligence system into one computational cadence creates unnecessary latency.

Instead:

```text id="phstqv"

     ↓

     ↓
Understand / Plan / Correct
```

The slower layer can still influence future fast behavior through consolidation.

This produces:

```text id="mxl1cb"

   ↔

```

rather than:

```text id="slg1cl"

   ↓
Slow Path
```

# 47. Core Architectural Principles

## Principle 1 — Multi-Substrate Intelligence

> Intelligence can be realized across physical, sensory, structural, neural, representational, generative, and human substrates.

## Principle 2 — Function-Tunnel Architecture

> Stable intelligence paths should be treated as reusable structural objects rather than repeatedly rediscovered computations.

## Principle 3 — Smallest Sufficient Intelligence

> Use the smallest substrate capable of safely resolving the distinction.

## Principle 4 — Selective Upward Escalation

> Escalate only when simpler intelligence cannot resolve uncertainty, novelty, or risk.

## Principle 5 — Downward Structural Consolidation

> Repeatedly successful and stable functions should become candidates for cheaper structural realization.

## Principle 6 — Bidirectional Migration

> Novelty tends upward; stability tends downward.

## Principle 7 — Multi-Timescale Intelligence

> Different intelligence substrates should operate at the timescale appropriate to their function.

## Principle 8 — Function-Tunnel Escape

> Every narrow fast path should expose a failure condition and escape route.

## Principle 9 — Structural Governance

> Capability, authority, policy, and routing must be explicitly separated.

## Principle 10 — Trace-Driven Evolution

> Runtime traces should drive Function-Tunnel growth, refinement, migration, and retirement.

# 49. What HSCI-003 Does Not Claim

This paper does not claim that:

3. smaller intelligence is always better;

7. runtime migration between substrates is currently solved;

# 52. Conclusion

Intelligence Before Representation changes the architecture of AI.

Once physical and sensory structures are allowed to participate in intelligent selection, intelligence is no longer confined to ANN, world models, or LLMs.

It becomes a distributed system of specialized substrates.

The fundamental path changes from:

```text id="r1t6a6"
Sense Everything
      ↓
Represent Everything
      ↓
Compute Everything
      ↓
Decide
```

to:

```text id="6itpms"
Sense Selectively
      ↓
Resolve Early When Possible
      ↓
Escalate When Necessary
      ↓
Consolidate When Stable
      ↓
Govern Every Path
```

Hardware Function Tunnels provide stable low-level paths.

CCC and Boolean systems provide structural triggering and control.

ANN specialists provide learned discrimination.

World models provide relational and temporal modeling.

LLMs provide flexible semantic reasoning.

Humans remain available for unresolved judgment and accountability.

These layers should not compete for ownership of intelligence.

They should cooperate.

The resulting Brain-Unit AI is therefore not:

> **one large model connected to the world.**

It is:

> **a governed network of intelligence substrates connected through Function Tunnels, dispatch structures, escalation paths, and structural learning.**

Its central runtime principle is:

> **Put the smallest sufficient intelligence at the earliest effective layer, and escalate only when necessary.**

Its evolutionary principle is:

> **Novelty moves upward. Stability moves downward.**

And its architectural objective is:

> **Right intelligence, right function, right substrate, right time.**
